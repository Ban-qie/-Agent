# 单任务执行与交接模板

每完成一个任务，将下面的记录写到 `docs/verification/<ID>/handoff.md`，在对应阶段卡上更新状态。记录私有结果的文件不得移入公开摘要。未通过的任务保留未勾选状态，并写清下一步。

V2—V4按 [小步执行协议](LOW_EXECUTION.md)执行；本模板简短填写即可，不为每次交接重写整套设计。卡内子步骤可记录在同一handoff，日志/报告按attempt编号新增，不覆盖失败。

```markdown
# 任务 ID / 标题
- 状态：未开始 / 进行中 / 通过 / 阻塞-缺输入 / 暂停-待人工调整 / N/A（原因）
- 当前子步骤（a/b/c）、前一子步骤验收：
- 前置任务与证据：
- 本次目标（一个行为）：
- 开始提交、已有未提交差异、实际输入文件 SHA-256：
- 涉及文件（已有/拟新增）：
- 请求/响应或领域契约变化：
- 正常样例与预期：
- 边界/失败样例与预期：
- 修改摘要与不兼容风险：
- 验收命令、退出码、通过/失败计数、证据路径：
- 实际模型调用：新增次数、已知费用、未知用量、预留、累计账目指纹：
- 首次失败和修复记录（不能只保留最后成功）：
- 当前阻塞ID、初次复现、已完成修复次数（跨会话累计）：
- 尝试1：根因假设、补丁/文件、复验命令/退出码、失败证据：
- 尝试2：根因假设、补丁/文件、复验命令/退出码、失败证据：
- 暂停时所需人工调整或缺失输入、恢复后的第一条命令：
- 当前提交/补丁与回退方式：
- 尚未验证：
- 下一任务 ID、第一步、所需输入：
```

任务太大时先追加两个更小任务卡：一张定义/实现纯函数或存储契约，一张接 API/页面。共享数据与权限设计不能凭模型猜测；先写可评审的 schema 和反例，再实施。涉及交易、对象授权、版本迁移的工作需要有真实行为测试；可逆文档/样式修改不必额外编写测试。

同一阻塞连续两次修复未通过，不再进行第三次试改：状态改为“暂停-待人工调整”，向用户说明任务、失败点、交接路径，请其人工调至medium后回复继续。未收到明确调整回复不得继续依赖工作；不得把模型调整等同于新的调用预算或部署授权。
