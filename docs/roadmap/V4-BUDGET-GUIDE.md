# V4 Qwen 与费用指南

## 两种边界

网站生产用户没有累计调用次数或累计金额配额。每个新分析任务可以使用最多 3 次内部 Qwen dispatch，自动重试为 0；这是单任务稳定性边界。开发和发布验收的项目累计 10 元上限只约束调试人员的真实调用，不限制受邀用户正常使用网站。

## 记账规则

每次 dispatch 在发送前写入 PostgreSQL `website_usage`。收到供应商 usage 后保存 token 与本地费用估算；没有可靠 usage 时保存 `unknown`，不得删除或按 0 元结算。相同 request ID 的幂等提交不能重复 dispatch；提交结果不确定时先查持久任务和供应商账单，不能换 request ID 盲重试。

## 新真实 smoke 的授权流程

1. 先读当前 PostgreSQL usage、旧归档、unknown 和 active task。
2. 固定一个未使用的 request ID、原题、最多提交次数、最多内部 dispatch、自动重试数和新增费用上限。
3. 计算授权后的绝对累计上限，不能重置账目、换用户清零或复用旧授权余额。
4. 获得用户对该 attempt 的明确授权后只提交一次，立即创建防重放标记。
5. 终态后核对 task、node、usage、模型调用数、容器健康和数值；保留失败与 unknown。

V4 已完成，不需要新的真实 smoke。日常 health/readiness、备份、恢复、故障注入和容量检查均不得调用 Qwen。
