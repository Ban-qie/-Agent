## 必须保留与可以移出的边界

| 类别 | 必须保留 | 当前不要求 |
| --- | --- | --- |
| 核心分析 | 三指标、明确期间/比较、日/月趋势、地区、追问/澄清/分支、图表/表格 | 商品/支付/状态扩展、贡献拆解、异常检测 |
| 正确性 | 口径/快照绑定、独立参考、条件继承、合法事实引用、空/失败区分 | 通用注册中心、独立证据平台、动态关系检索 |
| 输入/执行 | 请求限额、结构校验、不受信文本、只读/白名单、超时/资源限制 | 任意SQL、自由代码、上传、连接器 |
| 多用户 | 可信身份、服务端对象授权、私有历史/任务隔离、跨用户反例 | 邀请、分享、角色管理产品、自助注册 |
| 任务/费用 | 原子幂等、有限并发/等待、用户/全局限额、取消、中断恢复 | 分布式队列、SSE、自动续跑、额外编排 |
| 网站上线 | HTTPS/代理/生产配置、错误处理、健康检查、日志脱敏、备份恢复、负载实测、真实远程验收 | Kubernetes、高可用集群、复杂监控平台 |
| 简历交付 | 架构/个人贡献/演示步骤、代码和证据对应、许可/限制 | 强制录像、复杂报表或公开原始数据 |

Redis/PostgreSQL等是实现选择，不是为了简历强制加入；简单方案达不到已选并发/事务目标时必须升级。恶意或异常输入应被有界拒绝且不影响后续合法请求，不能用“永不崩溃”或“生产级”代替实测。

## 额度与实施规则

1. 一次认领一个任务ID，读取本页、[小步执行协议](LOW_EXECUTION.md)、[交接模板](HANDOFF.md)、任务及对应代码。先检查git状态，保留旧节点、失败证据、未提交修改和累计账目。按卡内子步骤验收，不一次改完整阶段。
2. 先复用现有测试/数据契约/鉴权组件；已有正确实现只补当前验收证据，不为满足清单另造一套模块。跨模块工作先定输入输出，再按契约/接入拆子卡。
3. 代码修改先跑相关离线测试，阶段出口跑完整相关回归。纯文档任务只检查差异、编号、链接，不跑模型或全量测试；同指纹已通过检查可复用，注明版本。
4. 模型开发/异常/负载测试默认fixture或stub；真实调用只补模型或目标环境必须的证据。**Codex开发额度与应用Qwen费用是两种消耗**，二者都通过缩小任务和减少重复验证节省，不能互相换算。
5. Qwen累计账目目前247次，已知估算0.04992810元、预留4.89元、2笔未知usage；项目验证累计上限10元仍保留。原193/247次campaign额度已用尽，不能重启/换用户清零。新真实验收前写清问题、最大调用数、绝对累计上限、失败保留和剩余费用检查。
6. 不默认重跑20+20。首轮上线smoke建议只取覆盖两用户/核心分析/追问的最多4个必要问题，每题最多3调用，总计最多12调用；这是待冻结计划建议，不是本次执行或自动追加额度。实际问题和环境确定后冻结，失败不自行扩预算反复重试。
7. 每卡交接短记：改动、命令/退出码、证据、失败、费用增量、下一任务；项目设计集中在 `docs/specs/core-release.md`，避免每卡写一份重复长文。数值/条件/越权/恢复阻塞未解决不得进下一卡。
8. 用户已要求多用户上线，可推进本地实现、测试和部署准备；到真实部署必须取得明确目标、账号/域名/访问范围及必要凭据。已有授权范围不重复询问；缺信息只暂停依赖部分。不擅自推送、公开数据、发送邀请/通知或购买资源。
9. V4-S07通过即可结束项目，V5所有模块默认未启用，不逐个要求实现。将来启用扩展仍必须继承同一权限、数据、预算和回归标准。
10. 同一阻塞连续两次有依据的修复仍未通过，必须保存复现、两次补丁/失败证据和账目增量，暂停本卡及依赖工作，申请人工从low调至medium；用户明确调整后再继续。初次复现不算修复尝试，次数跨会话保留。无法证明认证/迁移/并发安全时可提前申请；不自行切模型、不做第三轮盲改、不放宽断言或预算。
