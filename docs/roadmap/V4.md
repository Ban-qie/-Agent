# V4：稳定运行、真实部署与可审阅交付

V4 只在 V3-S09 已通过后开始，完成 V4-S01—V4-S07 后停止，不自动进入 V5。V4 的目标是把 V3 的本机 loopback 版本变成一个可验证的部署包，并在一个用户明确授权的目标环境中完成真实上线验收。V3 的离线浏览器通过、stub 延迟、localhost 截图和本地启动成功，均不能单独证明 V4 上线。

本卡与 [LOW_EXECUTION.md](LOW_EXECUTION.md) 配合使用。每个卡内子步骤必须按 a→b→c→d 顺序执行；前一步没有交接文件和通过证据，不得开始后一步。每个子步骤只做一个可验收行为，单次改动原则上不超过 5 个业务文件；超过时先拆卡并记录原因。

## V4 开始前的硬性输入

在 V4-S01a 结束前只允许读取和本地检查，不得猜测以下信息：

| 输入 | 必须明确的值 | 缺失时的处理 |
| --- | --- | --- |
| 目标环境 | Windows/Linux、版本、CPU/RAM/磁盘、时区 | 标记 `blocked-input/platform`，不得声称生产可用 |
| 访问地址 | IP/域名、HTTP/HTTPS、端口、允许访问来源 | 标记 `blocked-input/network`，不开放公网 |
| 代理/WSGI | 具体软件和版本、TLS终止位置、可信代理跳数 | 只做配置静态检查，不勾 S01 |
| 持久化/共享状态 | PostgreSQL 16；Redis 8.8.2；均由 Docker Desktop/Compose 启动；记录端口、卷、网络、TLS/认证和持久化策略 | 不允许保留 SQLite 多实例写入；Docker Desktop或数据库不可用时标记 `blocked-input/storage` |
| 认证 | 受邀账号来源、两测试账号安全注入方式、是否启用 QQ/OIDC | 不在聊天粘贴密码；缺失时只做 fixture |
| 数据 | Olist/快照许可、数据目录、快照 hash、是否允许历史迁移 | 没有许可或 hash 不验收真实数据 |
| Qwen | 服务端密钥注入方式、模型、真实 smoke 预算和绝对上限 | 免费/离线测试可继续；不得擅自发起付费调用 |
| 回滚 | 旧版本、备份目录、恢复负责人和允许停机窗口 | 缺失时不做真实发布 |

输入应写入 `docs/verification/V4-S01/input-freeze-attemptN.json`，秘密只写变量名和 hash，不写值。后续卡只能引用这份冻结文件，不能中途改变阈值、目标或预算来使测试通过。

V4 的存储边界冻结为：Docker Desktop 运行 PostgreSQL 16，保存用户、工作区、节点、结果、任务、授权元数据和 website usage/未知 reservation；Docker Desktop 运行 Redis 8.8.2，只保存共享 session、限流计数、短期分布式锁和任务协调状态。Redis 不是账目、结果或唯一任务真相来源；任何 Redis 丢失都必须能由 PostgreSQL 恢复或安全地把任务标为 interrupted。PostgreSQL 数据卷必须独立持久化并纳入备份；Redis 是否持久化只影响临时状态，不能改变业务账目。Docker Compose 文件只维护这一套依赖，不同时维护 MySQL 或 SQLite 多实例实现。

容器启动时机固定为：S01a 不启动容器，只读取环境和检查 Docker Desktop 是否可用；S01b 先创建并静态校验 Compose、环境模板、卷和网络；S01b 通过后才启动 PostgreSQL/Redis，使用 S01b 记录的唯一 Compose 文件；S01c/d 和 S02—S04 使用这套隔离实例。不得在项目外手动创建同名容器、使用未记录的镜像 tag、删除卷重置数据或让 V3 SQLite 服务连接到 V4 数据库。每次停止/重启/恢复都必须记录 Compose 文件 hash、镜像 digest、容器 ID、卷名和退出码。

## 通用证据规则

每个子步骤都必须新增不覆盖旧文件的证据：`docs/verification/V4-Sxx/<substep>-attemptN.{log,json,md}`。证据至少包含开始提交、工作区状态、命令、退出码、通过/失败计数、运行环境、输入指纹、账目 hash、模型调用增量、产生的文件和下一步。失败必须保留，不能删除锁、账目、节点或失败日志。

通过标准是“外部行为通过 + 证据完整 + 资源和账目守恒”。单元测试不能替代真实配置语法检查、实际备份恢复、实际 HTTP 访问或目标环境浏览器验收。stub 与真实 Qwen 的证据分开；不能把 stub 结果、旧 localhost 结果或未来功能写成生产结论。

共同禁止项：不重装依赖、不 reset/clean 工作区、不修改 V2/V3 历史来凑通过、不把 debug server 直接暴露公网、不把客户端 owner/header 当身份、不记录密码/Token/完整 Authorization/原始订单、不用重试掩盖未知费用、不因失败扩大预算、不实现 V5 功能。
